Script to keep cpu and ram threshold to 80% to avoid crash

Resource Control Script (Memory Threshold Protection)

On a shared compute server, excessive memory consumption by user workloads can make the system unresponsive or lead to application failures. To reduce the chances of server crashes, a lightweight monitoring script is used to continuously monitor memory utilization and automatically terminate recently started processes when memory usage exceeds a predefined threshold.

Note: Despite the page title referring to both CPU and RAM, the current implementation monitors memory (RAM) utilization only. CPU monitoring is not included in this version of the script.

Overview

The script, named resource_control_3.sh, runs continuously in the background and checks the system's memory usage every few seconds.

When memory utilization reaches or exceeds the configured threshold:

  • The script identifies the most recently started processes.
  • It forcefully terminates a predefined number of those processes.
  • Memory is freed, helping prevent the server from becoming unstable or crashing.

This script serves as a basic safeguard for environments where multiple users may execute memory-intensive workloads simultaneously.

Default Configuration

Parameter Default Value Description
Memory Threshold 80% Maximum allowed RAM utilization
Monitoring Interval 3 seconds Time between consecutive memory checks
Processes Terminated 3 Number of recently started processes to kill

Prerequisites

Before running the script, ensure the following:

  • The script is executed with root privileges.
  • Save the script as:
resource_control_3.sh
  • Make the script executable:
chmod +x resource_control_3.sh

Script

#!/bin/bash

# Threshold in percentage (e.g., 80 for 80%)
THRESHOLD=80

# Number of last processes to kill
N=3

# Interval between checks (in seconds)
INTERVAL=3

while true; do

    # Get the total and used memory in percentage
    MEMORY_USED=$(free | awk '/Mem:/ {printf "%.0f", $3/$2 * 100}')

    # Check if memory usage exceeds the threshold
    if [ "$MEMORY_USED" -ge "$THRESHOLD" ]; then

        echo "Memory usage is at $MEMORY_USED%, exceeding threshold of $THRESHOLD%."

        # Get the last N processes by start time and kill them
        LAST_N_PROCESSES=$(ps aux --sort +start_time | tail -n "$N" | awk 'NR==1{print $2}')

        echo "Killing last $N processes: $LAST_N_PROCESSES"

        for PID in $LAST_N_PROCESSES; do
            kill -9 $PID
            echo "Killed process with PID: $PID"
        done

    else
        echo "Memory usage is at $MEMORY_USED%, under threshold of $THRESHOLD%."
    fi

    # Wait before checking again
    sleep $INTERVAL

done

Running the Script

Once the script has been created and made executable, start it as a background process using:

nohup ./resource_control_3.sh > output.log 2>&1 &

Command Breakdown

Command Purpose
nohup Keeps the script running even after the terminal session ends.
> output.log Redirects standard output to a log file.
2>&1 Redirects error messages to the same log file.
& Executes the script in the background.

After execution, the shell returns a Process ID (PID) similar to:

[1] 25467

The returned PID confirms that the monitoring script has been started successfully.

Verifying the Script

To verify that the script is currently running:

ps -ef | grep resource_control_3.sh

or

pgrep -af resource_control_3.sh

To monitor the script's output in real time:

tail -f output.log

Operational Notes

  • The script continuously runs until it is manually stopped.
  • Memory usage is evaluated every 3 seconds.
  • If utilization exceeds 80%, the script terminates the three most recently started processes.
  • Processes are terminated using kill -9, which immediately stops them without allowing graceful shutdown.
  • The script does not identify the processes consuming the highest amount of memory; it simply targets the most recently created processes.

Startup Recommendation

As of 22-Oct-2024, this script is not configured as a systemd service. Therefore, it must be started manually after every server reboot.

Running the script immediately after system startup is recommended to ensure continuous memory monitoring throughout the server's uptime.

Limitations

The current implementation has several limitations that should be considered:

  • Only RAM usage is monitored.
  • CPU utilization is not monitored.
  • Recently started processes are terminated regardless of their actual memory consumption.
  • The script relies on forceful process termination (kill -9), which may interrupt running jobs without cleanup.
  • Automatic startup after reboot is not yet implemented.

Future improvements may include CPU monitoring, intelligent process selection based on memory usage, configurable exclusions for critical services, logging enhancements, and deployment as a systemd service for automatic startup.
